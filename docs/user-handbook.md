## 1. 个人用户首次使用

1. 打开部署时提供的控制台地址。本机局域网部署为 `http://localhost:8081`；远端设备必须能访问此地址。
2. 租户填 `default`，使用管理员分配的账号登录。新建账号首次登录必须修改密码。
3. 到“账号安全”修改密码、绑定 MFA，立即妥善保存恢复码。恢复码只能使用一次。
4. 到“设置 → API Key”按用途创建密钥。创建结果仅显示一次，复制后保存到设备的环境变量或凭据管理器。
5. 选择下面的资产采集、模型调用或 MCP 防护流程。三者分别管理不同流量，可以同时使用。

| 用途 | 最小权限 | 验证位置 |
|---|---|---|
| 终端资产采集、日志上报 | `sources:write` | 资产台账、接入管理 |
| 模型调用 | `models:write`，客户端读取模型列表时另加 `models:read` | 模型网关用量、运行时事件 |
| MCP 逐帧检查 | `policies:read` | 运行时事件 |
| 读取风险/报告的自动化 | `findings:read` / `reports:read` | 对应 API |

不要把平台登录密码当成模型 API Key，也不要把模型厂商的 Key 填入 AGF 客户端。

需要按 Agent 执行配额、隔离或本地模型限制时，在创建 API Key 时绑定对应 Agent。客户端无须自行声明 Agent；如果声明了其他身份，服务端会拒绝。操作步骤和验证方法见 [案件处置与 SOAR 指南](case-response-guide.md)。

## 2. 企业租户与账号

平台超级管理员在“设置 → 租户管理”创建组织，填写名称和唯一租户标识（如 `finance-team`）。随后从右上角切换到该租户，再在“设置 → 用户”添加租户管理员，分配初始密码。

平台超级管理员停用或重新启用组织时，应先核对租户名称和状态。若另一位管理员已经修改同一组织，页面会提示冲突并刷新列表；请核对新状态后再操作。调用 `PATCH /api/v1/tenants/{id}` 的脚本须携带租户列表中当前的 `directory_version`，并使用 `directory_name` 作为目录名称，例如 `{"name":"Finance Team","enabled":false,"expected_version":1}`。成功响应的 `version` 即更新后的目录版本；HTTP 409 表示旧版本，不能盲目重试。列表中的 `version`/`name` 属于企业资料编辑，与目录的版本/名称独立。旧脚本升级后须先读取租户列表再发送修改。

向成员提供：控制台地址、租户标识、用户名和初始密码。普通成员登录时必须填写所属租户标识；他们不能通过修改请求头访问其他租户。平台超级管理员可切换到其他租户进行管理。切换会刷新页面数据；密钥、策略、额度和通知渠道都在当前租户内配置。

租户管理员在“设置 → 用户”可修改成员角色，或停用、重新启用账号。停用会立即使该成员已有会话失效；不要用删除用户数据代替停用。若另一管理员或成员登录时更新了同一账号，旧页面的修改会显示 409 并自动刷新列表。核对最新角色、MFA 与状态后，再决定是否重新操作。API 调用 `PATCH /api/v1/users/{id}` 必须带用户列表返回的 `expected_version`，例如 `{"role":"auditor","expected_version":3}`；每次成功后使用响应中的新 `version`。首次登录、改密和 MFA 更新也会推进账号版本，因此冲突时不应沿用旧值强制重试。

当前租户的管理员在“设置 → 租户与白标”维护名称、套餐、区域和界面品牌，在“设置 → 网关配额”维护 Token 与并发限制。两处配置分别记录版本；若另一管理员先保存，页面返回 409 并保留当前草稿。先复制需要合并的输入，再确认加载最新资料，对照修改后重新保存。后台刷新不会丢弃冲突草稿。

“设置 → 口令策略”决定新密码长度、组成、有效期、历史和失败锁定，也可要求全员 MFA。开启强制 MFA 前，当前管理员必须先到“账号安全”绑定验证器并保存恢复码。多人同时编辑策略时，较旧版本返回 409；页面保留草稿并要求确认加载最新策略，避免把其他管理员刚加严的规则覆盖。只读成员可查看，但不能保存。

停用租户保留已有数据，同时阻止成员及该租户 API Key 继续访问。默认管理租户不能停用。恢复时由平台超级管理员重新启用。不要用删除数据库目录的方式停用组织。

首次接入多个组织时，可在两个测试租户各建一个同名测试资产，用各自成员登录核对台账只显示本组织的记录；把另一个租户的资产详情链接交给当前成员，应得到“未找到”，而不是显示对方资料。同名用户名可以分属不同租户，登录时必须填写对应租户标识，建议使用不同口令。运维人员还应运行 `agfctl db check-schema` 并确认退出码为 0；它会核对数据库的租户表策略和受限运行角色。业务验收应使用隔离测试租户，不要为测试停用正在使用的组织。

## 3. Windows / Linux / macOS 终端采集

在“接入指南 → 终端采集”下载当前实际存在的制品并核对 SHA-256。没有对应制品时，需要在目标系统构建 `agf-agent`；界面不会提供不存在的下载链接。

Windows PowerShell 示例：

```powershell
$env:AGF_AGENT_SERVER_URL = 'http://localhost:8081'
$env:AGF_AGENT_TOKEN = '<采集专用 Key>'
.\agf-agent.exe run --data-dir .\agf-data --interval 60
```

Linux / macOS 示例：

```sh
export AGF_AGENT_SERVER_URL='http://localhost:8081'
export AGF_AGENT_TOKEN='<采集专用 Key>'
./agf-agent run --data-dir ./agf-data --interval 60
```

程序以当前登录用户读取 AI/MCP 配置，必须由实际使用这些应用的用户运行。`collect --json` 只预览；`run` 才会发送报告。每台终端独立保留 `agf-data`，其中包含身份和断线队列。网络恢复后会补传；不要复制其他终端的身份目录。

到资产台账按主机名搜索，检查最近活跃、模型端点、MCP 和 Skill。资产发现本身不代表模型或工具流量已被拦截，需要完成下一节的代理配置。

发现或手工登记后如需修正归属信息，在资产详情点击“更正资产资料”，修改名称、负责人、部门、分级并填写原因。保存后可在最近变更中核对前后值；状态流转仍使用“评审与生命周期”。操作步骤与冲突处理见[资产接入与治理指南](asset-governance-guide.md)。

## 4. 模型网关与应用

单价、估算费用、日预算及查询操作见 [模型费用与预算指南](model-usage-guide.md)。所有金额以 CNY 元计价；历史误写为 USD 的接口名只作兼容，不发生汇率换算。

1. 在“模型网关”添加端点：厂商、厂商模型名、基址、凭据。基址应从厂商控制台/API 文档取得；保存后凭据不回显。
2. 先使用 Mock 端点测试；真实联调须按 [待验证清单](pending-verification.md) 完成相应条件。`AGF_MOCK_MODE=1` 不会向模型厂商发送真实请求。
3. 在支持 OpenAI 兼容协议的应用中设置 Base URL 为 `http://localhost:8081/v1`，API Key 为 AGF 模型调用专用 Key，模型填写已配置模型名或 `auto`。
4. 发送一个简短测试请求，到网关用量页检查调用记录，再到运行时防护查看策略判定。

| 应用 | 配置入口/方式 |
|---|---|
| OpenAI SDK / 自研应用 / LangGraph | 客户端 `base_url` 和 `api_key` 指向 AGF；模型使用已配置名称 |
| Dify | 在支持自定义地址的模型供应商配置中填写 AGF Base URL 与 Key |
| Cursor | 在允许自定义 OpenAI 基址的模型配置中填写；实际支持的模型功能由客户端版本决定 |
| Coze / 外网 SaaS | 先确认该产品允许自定义模型基址或插件；SaaS 不能直接访问 `192.168.*`，需要可达的 HTTPS 入口 |
| Claude Code | 模型接入使用平台根地址的原生 `/v1/messages`，按 [Claude Code 模型网关接入](claude-code-gateway.md) 设置；资产发现与 stdio MCP 见下一节 |

容器内 `127.0.0.1` 是容器自身。Docker Desktop 上访问宿主机模型一般使用 `host.docker.internal`，并限制模型服务的访问范围。

## 5. stdio MCP 防护

把客户端原先直接启动 MCP Server 的命令，替换为 AGF 代理；原命令放在 `--` 后面：

```powershell
$env:AGF_AGENT_SERVER_URL = 'http://localhost:8081'
$agfSecret = Read-Host 'MCP 专用 Key（policies:read）' -AsSecureString
$agfPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($agfSecret)
try { $env:AGF_AGENT_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($agfPtr) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($agfPtr); Remove-Variable agfSecret,agfPtr -ErrorAction SilentlyContinue }
.\agf-agent.exe mcp-proxy -- node .\your-mcp-server.js
```

Claude Code、Cursor 等客户端的 MCP JSON 配置示例：

```json
{
  "mcpServers": {
    "guarded-tools": {
      "command": "<agf-agent.exe 的完整路径>",
      "args": ["mcp-proxy", "--", "node", "<MCP Server 脚本完整路径>"],
      "env": {
        "AGF_AGENT_SERVER_URL": "http://localhost:8081"
      }
    }
  }
}
```

先在启动 Claude Code 的同一个终端会话中设置 `AGF_AGENT_TOKEN` 为 MCP 专用 Key，再启动 Claude Code；子进程继承该环境变量，代理不会把它传给原 MCP Server。不要把实际 Key 写入项目 `.mcp.json`、提交到版本库或与普通模型 Key 共用。GUI 客户端若不继承终端环境，应使用受控的系统凭据注入方式。启动后先执行一个无害的查询工具。在运行时事件中确认工具名、策略与处置结果。策略服务不可用时代理拒绝转发；stdout 仅输出 JSON-RPC，诊断信息写 stderr。不要把普通调试日志写到 MCP stdout。项目内的 [本地接入模拟验收](local-onboarding-smoke.md) 可先无真实 Key 验证配置发现和代理链路。

## 6. 策略、黑名单与配额

先在策略中心选择拦截点、动作与作用范围，使用表单生成 CEL/Rego，或编辑源码。保存时服务端编译校验；非法源码不会替换已有策略。先使用“只观察”配合“历史与验证”输入测试上下文，确认结果后再关闭只观察。

“历史与验证”可查看旧源码并恢复版本。恢复会创建一个新版本，保留之前的记录。策略和运行时配置更新后在后续请求中生效。“运行时防护”的拦截点模式、启用状态是当前接入状态，只在此查看；`policies:write` 账号才能新增、启停或删除黑名单。关闭自定义规则后仍可能命中内置规则，应查看具体拒绝原因。

配额按租户、Agent、会话以及 Token、次数、并发、金额分别计量。并发额度在响应或结束调用后归还；代理进程异常退出时由服务端租约回收。配额触发返回 429；模型调用可在“运行时防护 → 事件”查找策略名 `gateway-quota` 的限流记录，核对原因、作用范围和窗口后再修改额度，避免盲目放大全部限制。

通用运行时配额的创建、按版本修改、单个 Agent 目标和冲突处理见 [运行时配额指南](quota-guide.md)。已有规则修改必须携带当前 `quota.version`，成功保存保留已用额度；通用上限 `0` 表示没有额度，暂时停用应使用 `enabled: false`。

AgentTeams 单个 Worker 的日 Token 限额，在“云服务接入与操作 → Worker 配额治理”按“绑定 → 读取差异 → 确认同步 → 回读”完成，见 [Worker 配额接入指南](agentteams-quota-guide.md)。平台网关 Key 须绑定同一 Worker 资产才归入其目标规则；平台与云端用量分别计量，云限额配置同步不会自动接管全部厂商流量。

## 7. 通知

在“设置 → 通知”配置接收目标及参数，秘密字段只写入加密配置。先配置站内通知，然后在符合授权条件时测试外部渠道。测试页会显示实际回执、失败或模拟状态；模拟成功不表示外部系统已收到消息。

机器人 URL 本身含凭据，请只填在渠道目标字段。钉钉/飞书开启加签时将 `signing_secret` 填入秘密配置。邮件需配置 SMTP 主机、端口、发件人及认证凭据；企业短信使用组织自有 HTTP 网关协议。

## 8. 常见排障

| 现象 | 检查方法 |
|---|---|
| 401 | 检查租户标识、密码、MFA/恢复码或 Key 的有效期与撤销状态 |
| 403 | 检查账号/租户是否停用、角色及 Key 权限、策略拒绝原因 |
| 429 | 检查租户/Agent/会话配额及网关预算，等待相应窗口或调整配置 |
| 模型一直返回模拟内容 | 检查 Mock 端点及部署的 `AGF_MOCK_MODE`，查看 `X-AGF-Mocked` 响应头 |
| 上报没有资产 | 检查运行用户、应用配置位置、`collect --json` 和断线队列；以台账最近活跃时间验证 |
| 数据库不可用 | 配置了数据库时服务拒绝以空白内存后端启动；先恢复数据库和迁移，再启动服务 |
| 使用来源 CIDR 白名单后被拒绝 | 默认以 TCP 对端为来源。反向代理部署在 `.env` 设置 `AGF_TRUSTED_PROXIES` 为实际代理 IP/CIDR，重建服务；不要填所有地址 |

企业部署需要保留并备份加密主密钥、数据库与证据目录。备份和恢复步骤见 [运维手册](operations.md)。

## 9. 检测规则的发布、灰度与恢复

1. 打开“检测规则”，用搜索框查询全部规则；翻页会从服务端加载。
2. 点击“新建规则”或“编辑 / 版本”。模板中的 `key` 是稳定标识，更新时保持不变。
3. 修改检测条件和正负样本。点击“校验样本并发布”，只有定义合法、样本全部通过才会替换当前版本。
4. 可先将 `rollout_percent` 设为 0，再使用灰度滑块逐步放量。关闭开关后，后续扫描与网关请求不会使用该规则。
5. 在“版本历史”查看最近 100 次变更。恢复旧内容会重新回归并发布新版本，保留历史记录。

规则仅对当前租户生效。内置检测之外仍可能有运行时策略或黑名单拒绝请求，应查看拦截记录中的具体原因。

## 10. 报表、定时计划与下载

“报表 → 生成报表”选择类型、统计窗口与格式。PDF 适合阅读/打印；Markdown/HTML 适合留档；JSON 含元数据及正文；CSV 是按行导出的正文，便于后续处理。

“新建定时计划”填写名称、窗口、格式和 UTC cron。例如 `0 0 * * *` 为每天 UTC 00:00（北京时间 08:00），`0 0 * * MON` 为每周一。服务每 15 秒检查一次；停机期间的周期不补跑。先点“立即生成”并下载检查，确认后保持启用。

暂停和删除计划保留既有报告。执行失败会展示错误并重试。新生成的文件与 SHA-256 一起持久保存，升级排版程序不会改变已有制品。报表内标注哪些统计是生成时快照，哪些明细受所选时间窗口约束。

## 11. Azure 与 Messages 客户端

Azure 推荐 Base URL：`https://资源名.openai.azure.com/openai/v1`，模型填写部署名称。使用旧版 `/openai/deployments/部署名` 时，在端点配置的“Azure API 版本”填写版本；缺省为 `2024-10-21`。完整地址已有 `api-version` 查询参数时以地址为准。厂商密钥只填凭据字段。

平台提供 `/v1/messages`（文本、图片、自定义工具及 SSE），认证可使用 `x-api-key: 平台APIKey` 或 `Authorization: Bearer 平台APIKey`，需要 `models:write`。与 OpenAI 入口共用租户、策略、配额和计量。基础 Anthropic SDK 的 Base URL 填平台根地址，SDK 自行添加 `/v1/messages`。

`/v1/messages/count_tokens` 返回本地估算，响应头 `X-AGF-Token-Count: estimated`；计费仍使用上游实际 usage。扩展思考、签名块和 `context_management` 仅向 Anthropic 端点原生透传，Mock 只用于链路验证；消息经策略脱敏改写时会拒绝原生透传。其它厂商须使用基础跨协议转换。服务端工具、PDF/文件块及其它扩展尚未完整兼容。Claude Code 的接入步骤和边界见 [专门指南](claude-code-gateway.md)。真实厂商凭据链路仍需联调。

mTLS 反向代理必须同时配置 `AGF_AGENT_MTLS_TRUST_PROXY=1` 和限定代理地址的 `AGF_TRUSTED_PROXIES`，由代理校验客户端证书并覆盖证书头。来自未信任 TCP 对端的证书头会被删除。

## 12. 企业 OIDC 登录与 MFA

1. 个人用户可继续使用本地账号。企业管理员进入“设置 → 企业登录”，为当前租户配置企业身份中心。
2. 在身份中心注册 Web 客户端，选择 Authorization Code（授权码）和 S256 PKCE，授权范围 `openid profile email`。将控制台外部地址加 `/login/oidc/callback` 登记为唯一回调；生产环境使用 HTTPS。
3. 填写发现文档中的 Issuer、Client ID、Client Secret 和客户端认证方式。Basic/Post 必须与身份中心注册一致；Public Client 选择 None。Keycloak 可使用 realm 的 Issuer；其他身份中心填写其实际租户 Issuer，不能使用会返回不同 Issuer 的泛用入口。
4. 首次接入时按需开启“首次企业登录自动创建账号”，默认角色建议只读。可限制允许的已验证邮箱域名；此限制要求 ID Token 包含 `email` 与 `email_verified=true`。保存会真实读取发现文档，错误时不会显示配置成功。
5. 用户在登录页填写租户标识，点击“企业 SSO 登录”，在企业身份中心确认登录。请在原浏览器标签页完成，流程 10 分钟后过期。反向代理需支持 `/login/oidc/callback` 的前端路由回退。
6. 已开启本平台 MFA 的账号在回调页面输入验证码或恢复码。租户强制 MFA 时，新账号先进入“账号安全”，只可完成绑定。企业账号无需本地密码，但须在 SSO 登录后 5 分钟内操作。保存恢复码后重新 SSO 登录。

绑定或关闭 MFA 时若提示 409，说明账号在验证期间发生变化。重新打开“账号安全”检查当前启用状态，再重新验证；不要假定这次操作已经生效。数据库模式会把账号状态与 MFA 密钥记录一起提交或回滚，冲突时恢复码不会因这次关闭操作被消费。

企业身份按签名验证后的 Issuer 与 subject 建立独立账号，不按同名或邮箱合并本地账号。已有角色、停用状态不会在下次登录被默认值覆盖。关闭首次创建后，只有已纳管账号可继续登录。更换 Issuer 会建立新的身份边界；保持现有本地管理员可登录，以便修正配置。

多人维护企业登录配置时，页面会携带读取时的配置修订号。若另一管理员已保存，旧页面得到 409 并保留输入；先复制需要合并的修改，再确认“加载最新企业登录配置”，比较后重新保存。更换 Issuer 或 Client ID 时必须重新提供 Client Secret；旧密钥不会自动发送到新身份服务。只读账号可查看配置，不可保存。

常见错误：发现文档 issuer 不一致时修正为租户实际地址；“状态不匹配”时从登录页重新发起；“回调不同源”时使用管理员配置的控制台域名；邮箱域限制失败时检查 ID Token 的已验证邮箱声明。Client Secret 留空保留，改变 Issuer/Client ID 后需重新填写。

本地模拟验收步骤见 [OIDC 本地验收](oidc-local-verification.md)。LDAP / AD 的证书、账号映射、登录入口和排障步骤见 [LDAP / AD 登录接入](ldap-ad-guide.md)；企业 SAML 的 IdP 元数据、签名、账号映射和排障步骤见 [SAML 2.0 登录接入](saml-sso-guide.md)。已登录手机批准新浏览器的步骤见 [手机扫码登录](qr-login-guide.md)；厂商原生扫码按对应 OIDC/SAML 身份服务另行联调。

## 13. 日志接入与重新解析

进入“日志接入”后，列表只展示真实保存的接入配置。协议能力清单另见 /api/v1/sources/capabilities。本页面支持配置 HTTP Webhook 和 HTTP Pull；Syslog/Kafka/OTLP 等独立接收器仍按部署文档配置，能力清单不表示监听器已经启动。

### 平台推送（Webhook）

1. 新建日志源，选择 HTTP Webhook，填写名称，选择解析模板；留空则自动匹配已加载模板。
2. 保存后点击该行“接入指南”，获取专属地址 /api/v1/ingest/sources/{id}/events。
3. 点击接入指南中的“设置 → API Key”，有 `settings:admin` 权限的账号会直接打开创建窗口并预选 `sources:write`。将创建后只显示一次的 Key 用于发送平台的 `Authorization: Bearer` 请求头，或执行页面生成的安全输入 PowerShell 命令；API Key 自身绑定租户，无需额外填写 `X-AGF-Tenant`。没有密钥管理权限时请让组织管理员创建。
4. 检查响应 received（收到）、accepted（原文保存）、matched（解析命中）、failed（未保存）。未命中原文仍然保存，可后续解析。
5. 外部平台通过 HTTPS 反向代理接入。支持 UTF-8 文本、JSON 对象、JSON 数组和 NDJSON，每批最多 1000 条、2 MiB；超限整批拒绝，不静默截断。

### 平台拉取（HTTP Pull）

填写上游 HTTPS 日志 API 地址、拉取间隔（5–86400 秒）和 JSON 请求头，例如 {"Authorization":"Bearer YOUR_UPSTREAM_TOKEN"}。上游凭据加密保存，不回显；编辑时留空保留，输入 {} 清除；修改地址时必须重新填写凭据。仅本机 IP 测试地址可用 HTTP，不跟随重定向。

保存并启用后调度器自动拉取，也可点击“立即拉取”。上游通过 X-AGF-Next-Cursor 响应头返回下一游标，平台下次通过 X-AGF-Cursor 请求头发送。游标保存在数据库；全部原文保存成功才推进，未命中解析模板不阻断采集。没有游标的上游应自行提供增量窗口；不要用平台短期事件去重代替上游分页，重复返回会重复保留原文。

连接失败或上游错误显示于“最近错误”，约 60 秒后重试。副本间用源租约避免并发拉取同一源。编辑、停用或删除正在拉取的源时需等待本次任务结束，页面会提示。

### 重新解析

点击源名称，再点击“执行回放”；仅选择页面不会修改日志。平台使用此源当前解析模板（未指定时自动匹配）处理尚未解析的原文，显示检查、新解析和失败条数。已解析原文不会重复回放，删除配置保留历史日志与事件。列表搜索在服务端执行，可跨页查找。

### 会话与租户

有效登录周期内自动续期，同一标签页并发请求合并刷新；切换租户后仍通过原登录租户续期。退出登录会撤销服务端刷新凭据。改密、强制改密、账号停用或安全策略要求重新认证时，旧会话不能通过刷新恢复。

## 14. 解析模板预览与导出

在“接入管理 → 解析器”点击“预览”，平台会读取安装包中该模板的实际测试样本并执行解析引擎，展示归一化事件字段、未映射字段、派生表达式错误及耗时。支持内置日志文件和厂商样本目录的样本引用。

需要编写或修改模板时，点击“管理解析模板 / 新增解析模板”，先验证真实样本再保存。多人编辑冲突会保留草稿，可读取最新版本进行比较，明确采用后再重新编辑；见 [解析模板配置与版本冲突恢复](parser-configuration-guide.md)。

可粘贴自己的脱敏样本（最多 64 KiB）并点击“试解析”。此操作不创建日志或事件；未命中会显示原因，不显示伪造成功。安装包缺少样本时页面会说明，可手动粘贴样本。原生插件通过隔离采集器验证。

“导出模板 JSON”下载真实定义，包含引擎、模式、字段映射和版本。字段名保持原始 ECS 拼写，可用于后续导入。

### 创建、维护与恢复

1. 点击“新增解析模板”，粘贴 JSON 定义和脱敏验证样本；或在系统模板行点击“管理模板”创建副本。
2. 为模板设置唯一 key（字母、数字、短横线、下划线），保存后 key 不可更改。系统模板只读，副本仅对当前租户生效。
3. 点击“验证模板”检查实际解析结果。定义与样本各最多 64 KiB，保存时会再次校验；失败不会替换已生效版本。
4. 设置优先级和启停状态后保存。在日志源中选择该模板，后续采集和回放会重新读取配置，无需重启服务。多个实例共用 PostgreSQL 时读取同一配置。
5. 编辑自动保存为新版本；最近 20 个版本可恢复，恢复也产生新版本。多人同时编辑时，过期版本会被拒绝，请重新加载后合并修改。
6. 停用或删除绑定中的模板会阻止该源继续处理，应先为源选择替代模板。删除模板不会删除历史日志。列表的解析次数和命中率是当前实例启动以来的统计，非跨实例累计。

### 依据样本生成草案

在编辑器填写样本后，可选择默认“离线字段推断”并生成草案，不调用外部模型。JSON/KV/CSV 样本可自动推断形态和部分 ECS 映射，未映射字段仍需人工检查。

也可选择“模型网关”已配置的模型。样本最多 16 KiB，发送前替换可识别的凭据与个人信息；仍应先自行移除业务敏感数据。默认数据分级为“受限”，只允许本地部署模型；其他分级受端点上限、运行时策略和配额约束。模型请求使用统一网关计量，调用人须同时具备模型写权限。

返回的草案须在实际解析引擎中通过样本校验，再由用户确认保存；生成动作不会自动发布模板。模拟模型返回会明确标为离线推断。失败时可调整样本或直接编辑定义。
