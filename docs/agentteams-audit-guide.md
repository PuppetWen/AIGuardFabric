# AgentTeams 消息与调用审计接入

控制台「阿里云 → 消息与调用审计」提供绑定状态、接入示例、脱敏消息和 Trace/Span。该入口接收实际网关或 SDK 采集器上报；云资源盘点本身没有调用与消息审计接口。

## 先完成一次接入

1. 在「阿里云 → 云服务接入与操作」找到 AgentTeams，点击「配置与接入」，填写当前账号、地域和实例并启用，运行只读检查，再在「台账同步」完成完整盘点。可以先用 Mock 练习；Mock 事件和资产始终有标记。
2. 在「日志接入」新建日志源，选择 **HTTP Webhook · 平台或采集器主动推送** 并启用。原生 Syslog/OTLP 接收器和拉取源不能用于此绑定。此专用入口直接验证类型化事件，不要求再选择解析模板。
3. 回到「消息与调用审计」，选择日志源并绑定。管理员需要 `alicloud:write` 和 `sources:write`。平台冻结该源、当前云配置与盘点成员到 `bindingId`；请求体不能填租户、云账号、资产 ID 或授权结论。
4. 在「设置 → API Key」创建采集器 Key，仅授予所需的 `sources:write`，设置期限并妥善保存。此权限仍覆盖当前租户的日志源写入和管理，**不是单个来源或 Worker 的专用凭据**；给可信的采集器使用。页面不会显示已有 Key 的明文。
5. 复制页面的心跳 JSON，替换脚本中的地址、日志源 ID、绑定 ID 和 Key。心跳仅验证上报连通性，不增加调用量。收到 `accepted:1` 后刷新审计页查看记录。

```powershell
$base = 'http://localhost:8080'
$sourceId = '<日志源UUID>'
$bindingId = '<当前绑定UUID>'
$collectorKey = '<采集器API Key>'
$event = @{
  binding_id = $bindingId
  events = @(@{
    event_id = [guid]::NewGuid().ToString()
    event_time = [DateTime]::UtcNow.ToString('yyyy-MM-ddTHH:mm:ss.fffZ')
    kind = 'heartbeat'
  })
} | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri "$base/api/v1/alicloud/agentteams/audit-sources/$sourceId/events" `
  -Headers @{ Authorization = "Bearer $collectorKey" } -ContentType 'application/json' -Body $event
```

## 在业务采集器中生成事件

以下字段取自**实际发生的业务事件**，连通性测试不要手造业务调用。上报接口认证的是采集器，不能证明某 Worker 持有云端身份，也不能证明调用获策略授权。授权和敏感数据状态在调用链中保持“未知”。

| 字段 | 如何填写 |
|---|---|
| `event_id` | 业务事件稳定 ID；重试和多个采集器转发同一事件保持一致。1–256 个 ASCII 字母、数字、`_.:-` |
| `event_time` | 业务发生时间，RFC 3339；归一到毫秒。不早于当前绑定时间，最多晚到 30 天或超前 5 分钟 |
| `kind` | `call`、`message`、`task` 或 `heartbeat` |
| `from_worker` / `to_worker` | 完整盘点中的 Worker 名称；`call` 双方必填，`message` 发起方必填，`task` 至少一方必填 |
| `from_team` / `to_team` | 已盘点的成员团队。Worker 只属于一个团队时可省略，由平台补齐；多团队成员必须明确选择合法团队 |
| `task_id` / `trace_id` / `span_id` / `parent_span_id` | 实际关联标识，最多 128 个上述 ASCII 字符。不得塞凭据；没有实际标识就省略 |
| `status` / `duration_ms` | `success`、`error`、`unknown`，默认 `unknown`；实际耗时的非负整数毫秒，最多 7 天 |
| `message` | 可选 UTF-8 文本，最多 16 KiB。心跳不能携带成员、任务或消息 |

单批最多 1000 条、总请求不超过 2 MiB，并遵守日志源的单条消息大小限制。先验证整批再入库，非法尾项不会留下前半批。未知字段一律拒绝。

日志源的 `max_eps` 使用与普通日志上报共用的进程内令牌桶，整批容量不足返回 429，不消费半批令牌或写入部分事件；把批次减小到容量以内，稍后保留原内容重试。`max_eps=0` 表示不限速。多副本的源 EPS 仍为每进程口径，不是数据库共享总额度；平台请求限流另外生效。建议采集器每分钟发送一次心跳，便于识别断流，心跳也占接入容量。

同租户、当前云配置作用域和 `event_id` 相同且规范化内容一致，只算一次；内容不同返回 409，整批回滚。去重跨日志源生效，调用数不因转发重复增长。重试必须保留原始发生时间和内容，不能临时更换 ID 来掩盖冲突。

## 如何读取结果

- `GET /api/v1/alicloud/agentteams/audit-sources` 需要 `alicloud:read` 和 `sources:read`。`waiting` 表示尚未收到事件；`active` 表示近 5 分钟收到事件；`stale` 可能是长时间未收到事件或配置失效，查看 `acceptsEvents` 区分；`disabled` 表示绑定/日志源停用或源已删除。
- `GET /api/v1/alicloud/agentteams/audit-events?limit=50` 返回当前作用域最近 24 小时的事件，按发生时间及 ID 倒序。用 `nextCursor` 请求下一页；游标固定原窗口并绑定租户/作用域，30 分钟过期。刷新会开始新窗口。未来时间事件入库后，等其发生时间进入窗口才显示和计数。
- 页面只返回明确白名单字段和脱敏后的前 512 字符消息预览，不返回原始载荷、任意属性或云配置。原始日志保留在已有受限证据存储中，日志生产者应先脱敏，预览脱敏不等于销毁原始证据。
- 团队/Worker 展示的是**已采集调用数**，统计独立于分页；调用按被调用 Worker 计数一次。没有该 Worker 调用记录显示“未观测”。跨团队数只统计两个不同团队的 `call`，消息/任务/心跳不会增加调用数。覆盖范围未知，`completeWindow:false`，不能据此推断全天没有遗漏或风险为零。
- Trace、Span、父 Span 和任务 ID 用于关联；相同 Trace 的行可以在审计列表中对照。此功能尚不提供全图回放或自动云端配额同步。

## 配置变化与故障处理

完整盘点刷新后，若当前云配置、模式、团队成员与资产映射完全相同，平台同事务刷新绑定的盘点版本，保留 `bindingId` 和原绑定时间，采集器继续使用。成员/资产身份、云配置版本或日志源配置改变会使旧绑定失效；管理员重新盘点并绑定后再更新采集器。新绑定只接收新绑定时间之后的事件，切账号/实例时应隔离旧发送队列，禁止把旧账号事件换上新绑定 ID 重发。

| 返回或现象 | 处理 |
|---|---|
| 401 / 403 | 检查 Key 到期、租户停用与 `sources:write`；浏览器读页面还需要上述两个读取权限 |
| 400 | 检查整批格式、事件时间、真实成员团队和消息大小；响应不会回显秘密载荷 |
| 409，绑定失效 | 刷新页面，确认账号/实例和盘点，再重新绑定；采集器更新绑定 ID |
| 409，同 ID 内容冲突 | 查明业务 ID 重用或转发篡改；修正生产端后发送正确原始事件，不新造 ID |
| 503 / 中断 | 保留整批原内容重试；数据库模式审计、原始证据、Event 和待投递队列同事务提交，成功批不会重复计数 |
| 已接受但规则分析稍后出现 | 正常；事件经持久化投递队列进入后续联合分析，检查 NATS 和事件投递状态 |

PostgreSQL 模式提供跨实例去重、重启保留与租户行隔离。离线内存模式只适合本地模拟，重启丢失数据，不保证与配置存储的跨存储原子性。未经认证的原生 OTLP 日志不会自动变成可信的 AgentTeams 审计记录。实际云端采集器的字段与丢失覆盖情况，仍需第二阶段在真实业务平台验证。
