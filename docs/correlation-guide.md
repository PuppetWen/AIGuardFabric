# 关联分析接入与操作指南

入口：**检测规则 → 关联分析**。个人空间与企业组织各自保存规则、历史与事件；维护需要 `rules:write`，查看与试跑需要 `rules:read`。英文入口为 **Detection rules → Correlation**，界面提供中英文操作指南。

## 第一次使用

1. 在接入管理中连接日志源并回放样本。检查 `category`、`action`、`host`、`user`、`network` 和 `ai.session_id` 等归一化字段。
2. 选择时序、图路径、历史基线或检测规则匹配样例。样例只填入编辑器，默认停用，不自动写入业务事件。
3. 修改稳定标识、名称、等级、窗口和分组。不同租户不会参与同一条关联；没有实体或会话字段的事件不参与对应分组。
4. 在“条件与样本 JSON”中修改规则和两组事件。每组最后一条是本次触发事件，事件 ID 必须唯一。可从来源事件详情复制归一化 JSON；避免保存真实密钥或个人敏感内容。
5. 点击“试跑正负样本”：正序列必须命中，负序列必须不命中。确认结果后启用并“验证并保存”。服务端保存时会重新验证样本。
6. 推送新的测试日志，到风险发现、告警中心查看结果。证据链可逐条打开来源事件；调用链页签显示路径、时序或基线统计及规则快照。
7. 在设置中启用通知渠道，新告警进入持久队列。接入管理显示待分析/重试计数，通知设置显示投递与重试状态。

“登录后网络活动”示例用于学习配置，不应直接视作生产攻击规则。按组织风险条件收窄类别、动作和已命中的检测规则。

## 四类条件

| 类型 | 条件 | 判定与证据 |
|---|---|---|
| `match` | `rule_keys` 为检测规则标识 | 当前事件命中任一指定规则 |
| `temporal` | `steps` 每步含 `categories`、`actions`、`rule_keys`、`min_events`、`optional`；`order_required` 为顺序约束 | 有序步骤使用不同事件，完成计数后再进入下一步；同时间按接入顺序处理 |
| `graph` | `from_kind`、`to_kind`、`max_hops`（1–8），`event_filter` 限定事件 | 结构化实体共现构成关系边，跨源共享实体形成路径；每条边保留事件。正文猜测和相同厂商名称不充当身份边 |
| `baseline` | `metric`、`z_threshold`（0.1–100）、`min_samples`（至少 5）；`slot_by_time` 为 UTC 小时/星期分槽 | 从 SQL 历史重建均值和标准差；缺失值不当作零，异常值不参与学习，当前观测在学习前判定 |

基线指标：`outbound_bytes` / `network.bytes_out`、`inbound_bytes` / `network.bytes_in`、`prompt_tokens` / `ai.prompt_tokens`、`completion_tokens` / `ai.completion_tokens`、`cost_micro` / `ai.cost_micro`。费用单位为微元。按单条事件观测值建模，不把调用次数或静默期间补成观测值。启用时段分槽后，每个槽位需分别积累样本。

`group_by` 可选 `entity`、`source`、`session`、`none`。实体取最强结构标识，建议上游稳定提供 Agent/主机 ID。没有唯一标识时需核对主机别名；系统不会联网猜测 DNS 或 CMDB 映射。图跨源路径通常使用 `none`，再用事件条件收窄。图路径是调查线索，不能单独证明攻击或因果。

## 历史、恢复与失败处理

- 配置按租户校验版本，保留最近 10 个版本。冲突时草稿保留：点击“检查最新版本”，展开服务器内容并合并需要保留的改动，再“采用此版本号，保留草稿”。重新验证保存，仍会检查是否发生新的并发修改。历史内容可载入草稿，保存为新版本。
- 发布、停用或删除后，可在“审计日志”按主体名称 `correlation-rule`、主体 ID 与规则标识核对版本操作。数据库模式下，规则版本与成功审计共同提交；保存失败或版本冲突不会产生成功审计。需要确认是否生效时，以重新加载的规则历史和审计记录为准，不要根据旧编辑页判断。
- 停用阻止后续触发，删除保留历史；编辑已删除版本并保存可以恢复。规则新版本不会自动重跑已完成事件；使用日志回放产生新事件复测。
- 回执、发现和告警在同一 SQL 事务提交；重复事件、broker 重投和重启不重复登记该事件的结果。新事件的同类风险可以聚合到活动告警。
- 窗口为 1 秒至 7 天；时序子窗口须与配置一致。每次最多读取 10000 条候选事件，超出时保留失败重试，不截断后伪报成功。缩短窗口或使用来源/会话分组后重试。大规模压力验收属于第二阶段。
- 不开 NATS 时仍由 SQL 补偿扫描自动分析。SQL 不可用时保留失败重试。内存模式支持配置和试跑，重启不保留配置，不运行自动 SQL 分析。
- 基线是窗口统计，不是季节性预测模型；保留期限、字段质量和规则配置都会影响检测结果。

## 本地验证

在项目根目录加载 `scripts/env.ps1`，执行：

```powershell
cargo test -p agf-correlate
cargo test -p agf-api --lib correlation::
cargo test -p agf-api --test correlation_rules
```

数据库回归只接受 `agf_requirements_test_*` 隔离库：设置 `AGF_TEST_DATABASE_URL` 后执行 `cargo test -p agf-api --test correlation_database -- --ignored`。覆盖四类规则、乱序接入、新实例历史恢复、并发重复投递及租户隔离。
