# 平台策略发布、版本冲突与恢复

策略页面管理 AIGuardFabric 平台执行的策略。启用并保存后，平台模型网关和 MCP 代理的后续请求会读取持久化策略；`dry_run` 策略只记录判定。保存不代表阿里云 MSE、APIG 或外部 Agent 已更新，当前页面没有这些消费者的回读证据。

## 创建和更新

先用表单或 DSL 编写策略，检查语法、动作、作用范围、配额和降级模型端点。编辑器的代码检查是语法预检查，不验证未保存草稿的实际拦截结果。创建的名称在当前租户内唯一；同名创建返回 409 并保留草稿。需要修改已有策略时，从列表打开对应记录。

- `POST /api/v1/policies`：`expected_version` 省略或为 `0`。正版本参数返回 400，不会隐式覆盖同名策略。
- `GET /api/v1/policies/{id}`：取得当前策略及其 `version`。
- `PUT /api/v1/policies/{id}`：完整策略参数须包含正整数 `expected_version`，取自已查看的当前版本；名称保持原名称。
- `DELETE /api/v1/policies/{id}?expected_version=N`：软删除明确查看过的版本，签名历史仍可查询。

修改、删除缺少有效版本返回 400。版本已经变化返回 409。不要只把版本号换成最新值后重发旧草稿：读取最新内容，比较范围、动作和源码，明确采纳或重新编辑，再手动提交。

配额、降级模型端点必须属于当前租户且启用。Agent 范围必须指向当前租户仍在使用的 Agent；软删除或已归档资产不能继续作为新增策略范围。发布会重新检查这些条件，旧预演不保证提交时仍有效。

## 从历史恢复

`GET /api/v1/policies/{id}/versions` 返回服务器保存的签名版本。最多保留最近 100 个历史版本，当前版本单独保留；已软删除策略也可以读取历史。

选择可信历史版本，查看其动作、范围、源码以及与当前版本的差异，确认后调用：

```http
POST /api/v1/policies/{id}/versions/1/restore
Content-Type: application/json

{"version":1,"expected_version":3}
```

路径和正文的 `version` 必须一致。恢复版本 1、当前版本 3，会发布新的签名版本 4；历史版本 1 保持不变。软删除也占用一个版本，所以删除后恢复仍要使用删除后的当前版本。需要 `policies:read` 查看；创建、修改和恢复需要 `policies:write`，删除需要 `policies:delete`。

历史签名、内容哈希、租户、策略 ID 或版本次序不一致时拒绝读取或恢复，不会从客户端提供的历史内容重新签名。先保留错误和策略 ID，检查服务端主密钥与持久存储。不要直接编辑数据库历史或重新签名历史来掩盖校验失败。

## 提交和失败的边界

PostgreSQL 模式下，当前策略、签名历史、软删除和本次成功审计在同一事务中提交。依赖和租户在固定锁序下重新检查；等待审计锁后还会检查当前账号、角色、API Key、原登录会话安全状态和原 JWT 到期时间。版本冲突、权限变化、审计失败或数据库提交失败，都不会发布候选策略。

提交期间 JWT 到期返回 401；账号、安全设置、角色或密钥权限变化会拒绝提交。重新登录或恢复必要权限后，重新读取和比较再提交。刷新本地显示缓存失败只会记录服务日志，已经成功提交的持久版本仍是平台运行时依据。

离线模式的策略和审计只保存在当前进程内，重启不提供数据库级持久化。离线事务在同一配置锁内读取声明的配额、端点、固定租户目录、身份租户口令策略和该身份 MFA 记录；先完整验证和序列化候选，再调用可信同步审计存储，成功后直接发布候选。

离线权限检查先用现有认证规则完成授权及会话验证，并在前后读取一致的用户/角色/密钥和安全设置证据。提交回调只使用已确认不会重入配置锁的内置用户和角色读取，核对锁内证据、当前权限和原令牌到期时间。异步自定义认证后端无法在锁内即时给出记录时拒绝提交；请配置 PostgreSQL。用户、角色、密钥和 Agent 属于独立存储锁，执行提交前的新鲜检查时不会持有它们直到发布结束；配置锁不能保证这些独立身份变更与策略发布完全线性化。该方案只提供单进程配置和审计一致性，不代表跨进程事务或可撤销已经完成的外部请求。

保存后的运行时验证可使用模型网关或 MCP 代理发起一次受该策略范围约束的真实请求，并查看拦截结果和审计记录。预演只展示判定，不替代实际请求验证；平台发布也不承诺已在外部消费者热重载。
