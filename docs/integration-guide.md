# 外部平台接入与操作

控制台入口：集成管理 → 选择适配器 → 配置 / 业务调用与记录 / 接入指南。
使用当前选中租户的配置；读取总览需要 `integrations:read`，修改配置和执行需要
`integrations:write`。EDR 隔离和 SCIM 身份停用的真实写操作需先绑定资产、创建案件任务，再由具有 `cases:admin` 的人员审批；完整权限和步骤见[案件处置指南](case-response-guide.md)。

## 配置流程

1. 先选择测试群、测试工单项目或本地模拟接收端。个人用户可从一个 Webhook 开始。
2. 打开适配器配置，填写地址和凭据。Jira 项目、禅道产品、SMTP 主机和收件人等有独立字段；
   不常用设置放入“其他设置 JSON”。保存会校验设置，未配置完整可关闭“启用”保存草稿。
3. 凭据加密存储且不回显。留空保留原值；勾选清除会删除对应凭据。
   改变服务地址、SMTP 连接参数或 Slack API 地址时，必须重新输入凭据。
4. 模拟开关只产生带 `mocked=true` 的模拟回执。服务环境开启 `AGF_MOCK_MODE=1` 时，
   不能通过单个适配器设置绕过模拟模式。
5. 保存后检查 TCP 连通性。此操作只连接并关闭端口，不发送通知或登录凭据，
   不证明 TLS、账号权限或业务投递有效。UDP 没有连接握手，需在接收端核对日志。
6. 通知、工单和其它允许的业务操作，可在“业务调用与记录”填写一次测试调用，检查实际回执并到接收端核实。真实模式需要勾选本次调用确认；切换操作、修改内容或新建调用会清除确认。EDR/SCIM 的真实写操作必须走案件审批，集成页的 Live 模式只提供允许的读取与回执查看。

## 各平台需要填写什么

| 平台 | 设置 / 凭据 | 后续操作 |
|---|---|---|
| 飞书、钉钉、企业微信 | 机器人 `webhook_url`，按机器人设置填写签名凭据 | 发送通知 |
| Slack | `webhook_url`，可选 `channel`；更新需要 `bot_token` | 发送；按 channel 和原消息 ts 更新/撤回 |
| SMTP | `smtp_host`、`smtp_port`、`smtp_security`、`from`、`to`；需要认证时填 `smtp_user` 和 `smtp_password` | 发送邮件，默认 587 / STARTTLS |
| Webhook | `webhook_url`，可选 `auth_header_value` | HTTP 通知 |
| Jira | `base_url`、`project_key`、可选 `issue_type`；`user_email`、`api_token` | 建单；用工单 Key 回写；读取 issues；快照对账 |
| ServiceNow | HTTPS `instance_url`、可选 `table`；`api_token` | 建单；用 sys_id 回写；读取 incident；快照对账 |
| 禅道 | `base_url`、数字 `product_id`、可选 `opened_by`；`api_token` | 建缺陷；用缺陷编号回写；读取 bugs；快照对账 |
| Syslog | `endpoint` 如 `syslog://collector.example:514`；`protocol` 选 udp/tcp | 转发 RFC 5424；UDP 回执仅表示本机发送 |
| EDR | 兼容平台合约的 `endpoint`、`api_token`；默认 `dry_run=true` | 集成页 Live 可读取 hosts/events；真实主机隔离由已绑定资产的案件审批执行 |
| SCIM / IAM | SCIM 2.0 基地址 `endpoint`、`api_token`；确认支持 `PATCH /Users/{id}` | 在凭据资产绑定远端用户资源 ID；真实停用由案件审批执行，集成页 Live 只查看回执 |

EDR 适配器使用 `/v1/hosts/{id}/isolate` 等平台合约；不同厂商原生 API 需要适配网关。
真实隔离必须在其他设置明确填写 `{"dry_run":false}`，并在资产详情核对、绑定主机编号；然后在案件中选择该资产、提交任务并审批。未经审批，集成页直接 Live 写入会返回 412。
`dry_run` 是发给 EDR 的业务参数，仍会联网；“模拟模式”才是完全不联网。

SCIM 使用标准 `PATCH /Users/{id}` 将 `active` 设为 `false`；`id` 是身份平台资源 ID，不是邮箱。先在资产台账的 `credential` 资产绑定 `scim_user_id`，再在案件中提交停用任务并审批。SCIM 没有通用 dry-run，真实测试请使用专门测试账号。集成页直接 Live 停用同样会返回 412。两类任务超时或回执不确定时先核对远端状态，不要盲目重发。

## 读取、回写与对账

“发送”创建新消息/工单。“回写”要求已有远端对象编号；页面提供厂商对应样例。
Jira 工作流推进需填写实例实际的 `transition_id`，不能使用状态名称替代。
读取结果在回执的 `items` 中，下一页使用返回的 `next_cursor`；每次最多 1000 条。
对账使用传入的 `local` 快照，不会自动把查询结果导入资产台账或修改平台案件。
通知型适配器不提供无意义的读取/对账按钮。

此面板用于显式业务调用。自动告警投递在“设置 → 通知渠道”和告警升级路由中配置；
不能仅保存集成配置就认为自动通知已启用。

## 回执与重试

记录中的「查看」和「重新读取回执」严格只读。`pending_audit` 表示已有加密暂存的结果，
但本地回执发布和审计还未完成，页面仍显示 `uncertain`。请使用「恢复本地回执与审计」明确补交本地发布；
不重发原业务。停用或更换配置后也可恢复，失败保留原回执。状态、权限及中英文步骤见 [回执恢复指南](receipt-recovery-guide.md)。

每次调用带 UUID 请求编号、配置版本和操作类型。服务端先提交开始记录，再调用适配器，
最终提交加密回执。相同编号和相同内容返回原回执，不重复执行；改内容复用编号会冲突。
配置改变后须重新加载并核对目标。停用配置后拒绝新调用。

`succeeded` 表示适配器返回成功；模拟成功始终带 Mock 标记。
`failed` 表示明确失败；`uncertain` 表示超时或回执无法完整保留，远端可能已有副作用。
`started` 长时间未完成可能由进程或连接中断引起。
遇到后两种情况先核对远端记录，再决定是否新建调用；不要盲目重复隔离、建单或发信。
最近 50 条记录显示在面板中；数据库模式下配置与记录跨重启保留，离线内存模式不提供此保证。

## 验证范围

阶段一只使用模拟模式和本地 HTTP 假服务，覆盖配置加密、租户隔离、版本冲突、真实 TCP 探测、
Webhook 投递、Jira 创建/回写/读取/对账、失败回执和幂等请求。
EDR/SCIM 的审批边界、Mock 回执和本地 HTTP 模拟端已在阶段一验证。真实云凭据、企业群投递、实际设备隔离与身份停用在第二阶段按 [待验证清单](pending-verification.md) 验收。
