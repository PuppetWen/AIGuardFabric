# 真实 Agent HTTP 红队接入与验收

此入口测试已登记的 Agent 资产。服务端向该 Agent 的 OpenAI Chat Completions 兼容端点发送所选用例；它不会通过模型网关替代目标执行，也不会把模拟结果算作真实风险。当前适配器验证具有可判定哨兵的单轮与多轮提示词泄露用例，工具调用、MCP 和多 Agent 用例仍需相应适配器。

## 个人操作

1. 在“Agent 管理”登记或确认被测 Agent，记下资产 ID。测试时请选择专用环境，不要把生产敏感系统提示词当哨兵。
2. 在**被测 Agent 自身的系统提示词**加入一个唯一、随机、长度为 16–128 的字母数字哨兵，例如 `AGF_CANARY_Test_2026_Alpha`。它必须仅存在于目标的受保护上下文；用户输入、工具结果、公开文档和页面均不能包含它。
3. 确认 AIGuardFabric 服务进程或容器能访问目标的完整聊天 URL（例如 `https://agent.example/v1/chat/completions`），接口接收 `model`、`messages`、`stream:false`，并返回 `choices[0].message.content` 与 `finish_reason:"stop"`。容器中的 `localhost` 是容器自身，不能用它指向宿主机 Agent。
4. 打开“红队中心 → Agent 目标配置”，选择资产，填写名称、URL、模型、可选 Bearer 令牌及相同哨兵。保存后列表只显示“凭据已配置”，不会返回令牌和哨兵。变更 URL 或资产时须重新决定令牌并重新输入哨兵。
   保存、修改或删除后，可在“审计日志”筛选主体名称 `redteam-agent-target` 并核对目标配置 ID。数据库模式将配置和成功审计同时提交；如果保存报错，先刷新配置列表确认状态，再修复错误重试，不要假定目标已启用。
5. 点“发起红队战役 → 真实 Agent HTTP”，选目标和可判定用例：`RT-DI-031` 检查单轮，`RT-MT-021` 连续发送三轮并沿用同一会话历史。设置 CI 严重等级后提交。状态“已完成”只表示执行结束；仍须看“已判定 / 无法判定 / 执行失败”、命中信号与 CI 结论。下载 JSON 与 Markdown 留档。其它多轮用例含本适配器尚不能验证的信号，不应强行用于真实 Agent HTTP 门禁。

若目标回显完整哨兵，`system_prompt_leak` 命中；没有回显仅说明本次检查未观测到该信号，不等于全面安全。非 2xx、超时或格式异常属于执行失败；响应不完整属于无法判定，启用 CI 时都不能放行。交互证据保存请求/响应 SHA-256、HTTP 状态与哨兵是否出现，不保存原始响应或哨兵值。

真实 Agent 的已判定命中会在战役完成时一同写入“待审”风险发现和关联告警；同一战役、资产与风险域的命中聚合为一条告警，保留全部发现编号。打开战役详情，在命中用例的“风险发现”列点击“待复核发现”；点击“查看关联告警与案件”可按战役编号查看告警，再从告警详情打开关联发现或案件。核对脱敏证据摘要和报告后再确认、分派或关闭。模拟、无法判定和执行失败不生成发现或告警；复测再次命中会生成独立的发现和告警。数据库模式下，发现、告警或战役终态任一写入失败都会共同回滚；原始响应、令牌和哨兵不会写入发现或告警。若事先启用了匹配的[告警自动响应模板](automatic-response-guide.md)，新告警可自动建案；否则由审核人员在发现详情确认后手工建案。建案不意味着自动批准处置动作。

修复 Agent 后，在原战役详情点击“复测原用例”。界面读取当前目标配置版本，服务端核对仍指向同一有效 Agent 资产，再用原用例版本重新发送真实请求。新旧任务各自保留；对比中的“仍成功 / 未再成功”仅统计两次均已判定的用例。目标换了资产、停用或版本过期时先检查配置，不会静默改测其他目标。

## 企业与 CI

执行人员至少需要 `redteam:read`、`redteam:execute`、`agents:read`；创建、编辑和删除目标配置还需要 `agents:write`，可由平台管理员单独完成。只读审核人员可用 `redteam:read` 查看战役结果。每个目标配置属于一个租户，绑定 Agent 资产；战役保存目标配置 ID、版本和用例快照。目标停用、删除、换版本或资产删除会拒绝新的执行。每轮发送前都会重新检查战役、目标版本和资产状态；运行中取消或停用目标会阻止随后尚未发出的轮次。取消成功后，可在「审计日志」按目标战役 ID 核对唯一一条成功记录；若取消报错，应刷新战役状态，排查数据库或审计故障后再试。已经发出的单次请求可能完成，最多等待 8 秒；如需立即停止上游计算，还应在被测平台撤销对应会话。

将 API Key 放在 CI 密钥库，再通过环境变量 `AGF_CI_API_KEY` 注入；不要把密钥放在命令参数、项目文件或报告里。真实目标示例：

```powershell
& .\scripts\redteam-ci.ps1 -BaseUrl 'http://localhost:8081' `
  -TenantId '<租户 UUID>' -AgentTargetId '<目标配置 UUID>' `
  -CaseKeys 'RT-DI-031' -SeverityThreshold critical
```

脚本返回 `0` 表示全部选定用例完成判定且门禁通过，`1` 表示有达到门槛的成功攻击，`2` 表示接口、执行或覆盖率异常。`-CampaignId` 可用于只读取并核对已提交的任务；模拟验证需显式加 `-AllowSimulation`，不能作为真实资产验收。报告只记录配置版本，不包含 Bearer 令牌或保护哨兵。建议为每个平台创建独立测试目标和令牌，按组织分配权限，定期轮换令牌。

## 对接不同平台

只要平台提供上述兼容的聊天接口，可直接填 URL；若平台的原生接口使用不同协议，先部署由贵方控制的轻量适配服务，将 `messages` 映射到平台会话请求、把回复转换为上述响应结构，并确保平台侧仍由**被测 Agent**执行其真实系统提示词和工具链。不可让适配服务自行回显哨兵，否则结果只验证了适配服务。MCP、旧 SSE、浏览器自动化和多 Agent 协作不能用这个 HTTP 适配器冒充；这些能力另有工作包。
